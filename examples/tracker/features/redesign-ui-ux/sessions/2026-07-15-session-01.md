## Decisions (+ why)
- **UI-side input validation only for what the engine can't see** — duplicate employee names gate
  Continue in Setup (engine preflight doesn't check them; they crash Styler.map and can yield a
  nonsense roster). Night-team-empty is NOT gated in the UI — preflight owns it; UI copy adjusted.
- **Effort levels scale BOTH solver limits** (det 24/60/120 + wall 180/450/900) — engine requires
  the deterministic limit to bind first or rosters go machine-dependent (scheduler.py ~156-162).
- **Hard-fail routes back to Setup; Export warns independently** — banner and primary action must
  never contradict ("do not publish" vs. a primary export button).
- **Measured detail behind "Technical detail" expanders; glyph-substitution on rule names**
  (`->`→→ etc., display-only) — plain pass/fail statements by default, honest raw detail on demand.
- **Refresh-loses-state accepted as known limitation** (ISS-001) — inherent Streamlit session
  behavior, same as the old UI; a URL-state hack pre-demo judged riskier than the gap.
